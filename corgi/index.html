Foundational knowledge

What is an ETF?

An ETF is a regulated fund that holds a portfolio (stocks, bonds, commodities, crypto, etc.) and issues shares listed on exchanges. Corgi is the issuer; investors hold fund shares, not direct ownership of every underlying stock.

Two markets — primary vs secondary

ETF activity splits into two markets. Secondary is investors buying and selling existing ETF shares on exchanges — this is the vast majority of volume. Primary is Authorized Participants (APs) creating or redeeming shares directly with the fund — this changes shares outstanding and AUM, but happens far less often.

Five fixed roles — only the company inside each box changes. Fund accounting always pulls market data and operational truth into a fund administrator, which produces NAV and GL for the issuer.

Data pipelines

Receiving data is the easy part — a scheduled API pull or file drop. The hard part is when you pull, what you store, how you validate, and how you prove it later. Everything below assumes we persist data; we do not compute NAV from live API calls at publish time.

Why end-of-day?

Fund accounting runs on an as-of date, not in real time. A trade executed today does not settle today — US equities are T+1 (next business day); EU markets are typically T+2. Until settlement, the position is in investment receivable/payable, not cash. Market data vendors publish official EOD marks only after the close. Running the batch intraday would mean marking on incomplete prices and booking unsettled trades as settled.

EOD batch logic: wait for (1) market close + official prices, (2) custodian day-end file, (3) corp-action confirmations — then compute, reconcile, sign off, publish.

Ingest

Each feed runs on a schedule after vendor publication window. Ingest writes an immutable row — never overwrite the vendor payload.

curl / SFTP / vendor API → raw_ingest.{feed} (as_of_date, vendor, received_at, payload JSONB)

One JSONB column per feed preserves exactly what the vendor sent. If a computed NAV is wrong six months later, we can replay from raw without guessing whether the vendor or our transform was at fault.

Storage model

Three layers — not one table per API field, not one giant table either.

LayerSchemaContents
Rawraw_ingest.*Immutable vendor payloads (JSONB) + metadata. One table per feed type (prices, holdings, corp_actions…).
Normalizedcore.*Typed, queryable columns: price_eod, holdings_qty, corp_action. Parsed from raw; idempotent per (as_of, security, vendor).
Computedledger.*Datapoint values, GL lines, NAV components. Produced by formulas in the datapoint catalog.
Recon & reportingreporting.*Separate DB: exception log, vendor scorecard, SLA metrics. Does not block the NAV path.

Encryption: TLS in transit; AES-256 at rest (cloud KMS or on-prem HSM). Fund accounting data is not PCI, but it is fiduciary — treat as confidential. On-prem is viable for latency/control; cloud is viable for ops cost. Either works if access is role-scoped and audit-logged.

Validation & reconciliation

Three vendors per market-data pipeline (primary, backup, cross-check). When A ≠ B, pull C as tiebreaker.

flowchart TD A["Primary (A)"] --> CMP{"A = B?"} B["Backup (B)"] --> CMP CMP -->|Yes| OK["Use consensus value"] CMP -->|No| C["Cross-check (C)"] C --> V{"A = C?"} V -->|Yes| FLAG_B["Flag B · use A · log exception"] V -->|No| W{"B = C?"} W -->|Yes| FLAG_A["Flag A · use B · log exception"] W -->|No| ESC["Escalate — block NAV · manual review"]

Every exception writes to reporting.vendor_exceptions: field, as_of, vendor flagged, values from A/B/C, resolution. Over time this becomes a vendor reliability scorecard — which feed is actually worth paying for.

Three sources are enough for a tiebreaker — a fourth is diminishing returns unless SLA math shows residual risk above appetite. If A, B, and C all disagree, that is a block-NAV event, not an auto-resolve.

Transform

Normalized → computed via the datapoint formulas (detail cards). Transforms are deterministic, versioned, and replayable from stored inputs. No transform runs without persisted raw + normalized inputs for that as_of date.

Retention

SEC Rule 204-2 requires investment advisers to retain books and records for at least five years (first two in primary office). NAV history, GL, reconciliation logs, and vendor raw payloads qualify. Design default: 7 years online, then archive to cold storage — covers examination cycles with margin. Immutable raw JSONB makes replay and audit defensible.
